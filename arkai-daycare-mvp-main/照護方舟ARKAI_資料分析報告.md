## 0. 摘要（先看這段）

本報告把「投資簡報的故事」還原成**可實作的資料分析規格**，聚焦今天定調的兩大實務需求：

1. **確定是否開案**（開案前的門檻效益初篩）
2. **在案中個案的內容**（案中的即時照護與紀錄）

外加一條延伸：**手環可調整為「體能鑑測」工具**。

三個關鍵結論：

- **產品的技術骨幹不是「自動診斷」，是「地端資料安全分流」**。所有分析先過一層地端醫療 NER，判斷資料「能不能出門」，再決定走地端 RAG 或去識別化上雲。開案決策與案中紀錄，都是跑在這條管線上的兩個應用。
- **開案決策 = 純規則運算（可 5 週內做真的）**。輸入標準量表（Barthel／IADL／NPI-Q／跌倒史），輸出「跌倒風險燈號 + 每月人力成本 + 開案建議」，全程地端、個資不出門，可追溯。
- **案中內容 = 地端即時預警 + 生成式 SOAP 紀錄**。多模態手環；語音口述在地端結構化為 SOAP 與家屬聯絡簿；只有「去識別化的護理措辭潤稿／醫學術語摘要」才選擇性上雲——這正是對標 Jubo（雲端）的差異化。

### 2.2 先分清楚：誰是競品、誰是客戶

「參考來源」不等於「競品」。錯把客戶當競品，會導出「我們把大家的功能組起來」這種**沒有護城河的定位**。正確分類：

| 對象 | 是競品嗎 | 角色 |
|---|---|---|
| **Jubo AI** | ✅ 直接競品 | 雲端生成式照護紀錄 SaaS 廠商，在 SOAP/紀錄正面對撞 |
| **照管家** | ✅ 直接競品 | 日照管理 SaaS 廠商，在個案管理/評估/聯絡簿正面對撞 |
| **AIoT 監測廠商**（鑫淼所用系統的供應商） | ✅ 競品 | 賣人臉辨識/軌跡/離床偵測的硬+軟體廠 |
| **鑫淼天使居** | ❌ 不是競品 | 一家**日照中心＝潛在客戶/場域**；其監控只是「日照現場長怎樣」的參考 |
| **smartagedcare** | ❌ 不是競品 | 產業目錄/協會 |

### 2.3 能力矩陣（對真正的競品）

| 能力 | Jubo（雲端 AI 紀錄） | 照管家（日照 SaaS） | AIoT 監測廠商 | **ARKAI（本產品）** |
|---|---|---|---|---|
| 生成式護理紀錄 / SOAP | ✅ 強 | ➖ 表單為主 | ❌ | ✅（地端） |
| 多模態即時生理監測 | ➖ 手動輸入生命徵象 | ➖ 手動 | ✅ 影像/軌跡 | ✅ 手環融合 |
| 離床/跌倒即時預警 | ❌ | ❌ | ✅ | ✅ |
| 開案風險/成本試算 | ❌ | ➖ | ❌ | ✅（規則引擎） |
| **資料不出機構（地端物理隔離）** | ❌ 雲端 | ❌ 雲端 | ➖ 多半回傳雲端 | ✅✅ 架構與UX差異 |
| 個資合規（2026 最嚴法規） | 靠雲端合規承諾 | 靠雲端合規承諾 | 視廠商 | 物理隔離，天然合規 |

### 2.4 護城河：不是「功能組合」，是「架構級錯位」

⚠️ **要避免的錯誤定位**：「ARKAI ＝ Jubo 的紀錄 ＋ 監測廠的即時監控 ＋ 開案試算」。這是 A+B+C 堆疊，投資人會立刻反問「**那 Jubo／監測廠為什麼不能自己補上缺的那塊？**」——講不出來就沒有護城河。

**能撐得住的三條可防禦性論點：**

1. **創新者的兩難（最硬）**：Jubo／照管家的護城河建立在「雲端＋資料集中（Jubo 宣稱 30 億筆）」。跟進地端邊緣運算＝**自廢資料護城河、砍掉雲端訂閱模式**，結構性不願意快速跟進。這是最大的 wedge。
2. **法規時間窗**：2026 最嚴醫療個資／資安法規讓「上雲」變成負債，「物理隔離」天然合規。在「日照專用地端」這個利基當 first-mover。
3. **平台／閘道鎖定**：把自己做成機構內「地端去識別化標準閘道」，其他 IoT 輔具廠（智慧尿布／AI 膳食相機／監測手環）要進機構都得對接你 → 地端側的網路效應與轉換成本。

**要對自己誠實的風險**：on-prem LLM 盒正在商品化，**單靠「地端」很薄**、會被跟上。真正的護城河靠 (2) 時間窗 ＋ (3) 閘道標準 ＋ 長期累積的去識別化趨勢資料，不是功能組合。

> **一句話定位（修正版）**：ARKAI 不是把競品的功能組起來，而是賭一個**架構級錯位**——在 Jubo／照管家因商業模式無法輕易跟進的「地端」這一側，先拿下對雲端最有顧慮的日照機構，再把自己做成機構內 IoT 必須對接的地端去識別化閘道。
>
> **灘頭客戶（ICP）**：對 2026 法規最敏感、最不敢上雲、負責人會因資安睡不著的機構——對他們「地端」是 must-have，不是 nice-to-have。

## 3. 技術骨幹：地端 NER 資料安全分流

> 這是 v0.1 討論定調的真正核心。開案決策與案中內容，都是跑在這條管線上的應用。

### 3.1 管線總覽

```
長照/醫療紀錄輸入（病歷、護理紀錄、個案紀錄、家訪、語音口述）
      │
 ①地端接收（閘道層）— 資料一律先落地端，不預設外送
      │
 ②地端輕量醫療 NER / 分類 — 把每段內容打標籤：
      ├─ 高敏感個資 : 姓名 / 病歷號 / 身分證 / 地址 / 聯絡方式
      ├─ 臨床資訊   : 疾病 / 症狀 / 用藥 / 檢驗 / 照護風險
      └─ 照護脈絡   : 家訪 / ADL / IADL / 跌倒 / 失智 / 壓瘡 / 管路
      │
 ③安全分流
      ├─ 含高敏感 → 只走【地端 RAG】比對院內 SOP / 照護指引（如 RAGi 類地端知識庫）
      ├─ 已去識別 → 可選擇性送【雲端】：醫學文獻查詢 / 術語摘要 / 護理計畫措辭生成
      └─ 不確定   → 擋下，標記「需人工確認」
      │
 ④輸出 — 來源可追溯的摘要；標示哪些欄位被遮蔽；不給診斷，只給參考 + 待確認事項
```

### 3.2 地端 / 雲端責任切分（重要：決定資料流）

| 功能 | 地端做（預設） | 雲端做（去識別、可選、可追溯） |
|---|---|---|
| 開案風險/成本試算 | ✅ 全部（純規則運算） | — |
| 即時生理預警 / 離床偵測 | ✅ 全部 | — |
| SOAP 護理紀錄結構化 | ✅ 抽取 + 帶入生理數值 | 只有「潤稿成合規措辭」可選上雲 |
| 家屬聯絡簿草稿 | ✅ 彙整 | 只有「白話改寫」可選上雲 |
| 醫學術語摘要 / 最新文獻建議 | — | ✅（輸入已去識別化為「趨勢波動」） |
| 護理計畫措辭生成 | ➖ 可地端小模型 | ✅（去識別後） |

> 設計原則：**個資與可識別臨床脈絡永不上雲；上雲的一律是「去識別化的趨勢/術語」，且回傳結果必須標來源**。居家/個人端（居服到府、獨居長輩）沿用同一條管線，只是主機微型化為「個人地端盒」，多一層個人端防護。

### 3.3 端到端資料流總覽（input → logic → output）

一句話：**所有資料先落地端，逐層打標籤與分流；處理後只把「去識別化的趨勢/術語」選擇性上雲；最後一律人審才入正式檔。**

```
L0 來源 ─▶ L1 閘道接收 ─▶ L2 NER/分類 ─▶ L3 安全分流 ─▶ L4 處理 ─▶ L5 儲存 ─▶ L6 輸出+人審
 表單                   綁ID          打PII/臨床標籤    地端/雲端/人工   規則·閾值·SOAP    主檔+趨勢庫   三畫面
 串流                   落raw         數值類跳過NER      route+稽核      ·趨勢·體能        (加密)        +稽核軌跡
 語音 · 量測
        └───────────────────────── 全在地端 ─────────────────────────┘   （雲端僅收去識別趨勢/潤稿）
```

| 層 | Input | Logic | Output | 位置 |
|---|---|---|---|---|
| **L0 來源** | 開案表單勾選／手環·／社工語音／人工量測 | — | 原始事件 | 地端 |
| **L1 閘道接收** | 原始事件 | 綁 `case_id`＋timestamp；原始落地端 raw store | 標準化事件 | 地端 |
| **L2 NER／分類** | 文字類事件 | 醫療 NER 標 PII／臨床／照護脈絡；**數值類跳過 NER 直送規則引擎** | 帶標籤事件 | 地端 |
| **L3 安全分流** | 帶標籤事件 | 含 PII→地端 RAG；去識別→可雲端；不確定→人工佇列 | 路由決策＋稽核紀錄 | 地端 |
| **L4 處理** | 路由後資料 | 開案規則引擎／即時閾值引擎／語音→SOAP／趨勢聚合／體能聚合 | 燈號·成本·警報·SOAP·趨勢 | 地端（雲端僅去識別潤稿/摘要） |
| **L5 儲存** | 處理結果 | 個案主檔（加密含 PII）＋去識別化趨勢庫 | 持久化 | 地端（趨勢庫可同步雲） |
| **L6 輸出＋人審** | 處理結果 | **護理師確認才入正式檔**；顯示遮蔽欄位＋來源 | 三畫面／聯絡簿／稽核軌跡 | 地端 |

> 兩條應用（開案、案中）**共用同一條 L0–L6 管線**，差別只在 L4 的處理器不同。以下各走一遍實際資料。

### 3.4 走一遍 A：開案決策（實際數字）

**INPUT（地端表單，陳O奶 82 歲）**
```
PII      : 姓名「陳O奶」
結構化   : CDR 0.5、慢性病[高血壓]、近3月跌倒 1 次、輔具 助行器、鎮靜藥 無
Barthel  : 進食10 洗澡0 修飾5 穿脫5 大便10 小便5 如廁10 移位15 行走10 樓梯5 = 75（中度依賴）
NPI-Q    : 焦慮 severity2、憂鬱 severity2
```

**LOGIC**
```
L1 閘道 : 指派 case_id=C-0007；PII「陳O奶」→ 地端保險庫；表單數值抽出
L2 NER  : 「陳O奶」→ 標 PII → 遮蔽為 [姓名]；Barthel/NPI 為結構化分數，跳過 NER 直送規則
L3 分流 : 全為地端規則運算，無需上雲 → route = LOCAL_ONLY
L4 規則引擎：
  fall_score = 25(跌倒史) +0(慢性病1<2) +15(助行器) +0(移位15+行走10=25>20)
             +0(CDR0.5<1、無遊走/去抑制) +0(無鎮靜藥) = 40  → 🟡 黃燈
  care_weight = 1.0 +0.5(ADL中度75) +0.15×2(焦慮·憂鬱中度) = 1.80
  est_cost    = 1.80 × 0.53 × 22天 × NT$220 ≈ NT$4,600/月
  排除條件    = 無命中
  決策矩陣[黃燈 × 中成本] → 「⚠️ 評估量能」
```

**OUTPUT（畫面一）**
```
[姓名] 陳O奶 ｜ 跌倒風險 🟡黃燈(40) ｜ 預估人力成本 ≈NT$4,600/月 ｜ 建議：⚠️評估量能
稽核軌跡：姓名欄已遮蔽 ／ 本評估全程地端、未上雲 ／ 分數為輔助排序、非醫療診斷
```

### 3.5 走一遍 B：案中語音 → SOAP

**INPUT**
```
語音(台/國語)：「陳奶奶今天早上血壓正常，但下午吃藥時有點抗拒，情緒不太好」
併行串流     ：手環當下 HR 82、SpO₂ 97%；上午人工量測 BP 128/78
```

**LOGIC**
```
L1 閘道 : 語音 → ASR 逐字稿，綁 case_id=C-0007 + timestamp
L2 NER  : 抽實體 → [對象:陳奶奶→PII遮蔽]、[時間:上午/下午]、[生理:血壓正常]、
                    [行為:服藥抗拒]、[情緒:情緒不佳]
L3 分流 : 逐字稿含姓名+可識別脈絡 → SOAP 結構化「在地端」做
          O 欄數值一律由地端實測帶入(BP128/78、HR82、SpO₂97)，不讓 LLM 生成數字（防幻覺）
          (可選) 僅把去識別後的 A/P 措辭送雲端潤稿 → 本例 route = LOCAL（未上雲）
L4 SOAP 組裝：
  S: 服藥抗拒、情緒不佳
  O: BP128/78(正常，量測帶入)、HR82、SpO₂97%；服藥抗拒行為
```

## 4.【項目一】確定是否開案 — 資料分析

### 4.1 開案到底在問三件事

機構負責人看到一位新長輩，心裡真正要一秒決定的是：

1. **收不收得起？**（照顧風險有多高，會不會出事）→ 跌倒風險燈號
2. **人力？**（要投多少人力＝?）→ 每月照顧人力成本
3. **有沒有絕對不能收的紅線？**（超出機構量能/收托條件）→ 排除條件檢查

### 4.2 輸入資料（開案評估表）

全部是長照現場既有的標準量表，不需要長輩戴任何裝置就能填：

| 類別 | 量表 / 欄位 | 內容 | 用途 |
|---|---|---|---|
| 基本 | 姓名*、年齡、性別、失智診斷（無/CDR 0.5~3）、慢性病清單、目前用藥 | — | 基礎 + 排除條件 |
| **ADL** | **巴氏量表 Barthel Index**（10 項，0–100） | 進食/洗澡/修飾/穿脫/大便/小便/如廁/移位/行走/上下樓梯 | 依賴程度 → 人力權重、跌倒 |
| IADL | **Lawton 工具性量表**（8 項，0–8） | 電話/購物/備餐/家務/洗衣/交通/服藥/理財 | 輔助分級（日照較次要） |
| **BPSD** | **NPI-Q**（12 症狀 × 嚴重度 1–3） | 妄想/幻覺/激動攻擊/憂鬱/焦慮/欣快/冷漠/去抑制/易怒/異常動作/夜間行為/食慾 | 照顧難度、跌倒、人力 |
| 認知 | SPMSQ 或 MMSE 或 CDR | 簡易智能/失智分級 | 引導難度 |
| 跌倒 | 近 3 個月跌倒史（次數）、目前行走輔具 | — | 跌倒風險主因子 |

> `*` 標星欄位＝高敏感個資，進地端 NER 後不上雲；風險/成本運算只用「分數」不用姓名。

### 4.3 分析邏輯 A：跌倒風險指數（紅／黃／綠燈）

以 **Morse 跌倒量表** 為骨架，針對日照場景改良（日照通常無靜脈輸液，改以鎮靜藥/姿勢性低血壓補位），並用 Barthel 的移位/行走項自動推導步態：

```text
fall_score = 0
# 1. 跌倒史（近3個月）
fall_score += 25   if 有跌倒史
# 2. 續發性診斷（慢性病 ≥ 2）
fall_score += 15   if 慢性病數 ≥ 2
# 3. 行走輔具
輔具 == 無 / 輪椅代步          → +0
輔具 == 拐杖 / 助行器           → +15
輔具 == 需扶傢俱 / 攙扶行走      → +30
# 4. 步態（由 Barthel「移位 + 行走」自動判讀）
fall_score += 20   if (移位分 + 行走分) ≤ 20   # 虛弱/不穩
# 5. 心智狀態（CDR≥1 中度以上失智 or BPSD 遊走/去抑制 → 高估自身能力）
fall_score += 15   if CDR ≥ 1 or NPI_遊走 or NPI_去抑制
# 6. 日照補充項
fall_score += 10   if 服用鎮靜安眠藥 or 姿勢性低血壓

# 燈號
0–24   → 🟢 綠燈（低風險）
25–44  → 🟡 黃燈（中風險，需防跌關注）
≥45    → 🔴 紅燈（高風險，需防跌配套/1:1）
```

> ⚠️ 分數是**相對排序與提示**用途，不是醫療診斷；閾值需由合作機構護理長試用校準。

### 4.4 分析邏輯 B：預估每月照顧人力成本

概念三步：**照顧權重 → 換算每日工時 → 乘上天數與時薪**。權重把「ADL 依賴 + BPSD 難度 + 跌倒 + 失禁」轉成一個相對負荷數。

```text
# 步驟1：照顧權重 care_weight
w = 1.0                                   # 基礎陪伴
# ADL 依賴（Barthel 分級）
Barthel 0–20   完全依賴 → w += 1.5
        21–60  嚴重     → w += 1.0
        61–90  中度     → w += 0.5
        91–99  輕度     → w += 0.2
        100    獨立     → w += 0.0
# BPSD（每個中/重度症狀）
w += 0.15 × (中重度 BPSD 症狀數)
w += 0.35  if 有激動攻擊 or 遊走          # 可能需 1:1
# 跌倒
w += 0.30  if 跌倒紅燈
# 失禁（Barthel 大便/小便控制 = 0）
w += 0.30 × (失禁項目數)
# 重度認知（需全程口令引導）
w += 0.20  if 認知重度

# 步驟2：換算每日照顧工時
# 校準基準（用鑫淼真實比 1:7.5）：
#   15 位個案 : 2 位照服員 × 8hr = 16 工時/日  →  平均 1.07 工時/人/日（w̄≈2.0 時）
#   k = 16 / (Σ w of 15 典型個案)  ← 用機構實際個案組成回歸校準
daily_hours = w × k                        # 示範取 k ≈ 0.53

# 步驟3：月成本
monthly_cost = daily_hours × 上課天數(22) × 照服員時薪(NT$220)
```

**試算範例**（中度依賴 Barthel 75、2 個中重度 BPSD、黃燈、無失禁）：

```
w = 1.0 + 0.5(ADL中度) + 0.30(2×0.15 BPSD) = 1.80
daily_hours = 1.80 × 0.53 ≈ 0.95 hr/日
monthly_cost ≈ 0.95 × 22 × 220 ≈ NT$ 4,600 /月（純第一線人力分攤）
```

> ⚠️ 此數字是**個案間相對成本排序**用，讓機構「一秒比較 A 案 vs B 案誰更吃人力」。`k` 與時薪必須用該機構實際薪資結構校準後才可對外報數。

### 4.5 開案建議：決策矩陣

先過**排除條件（絕對紅線）**，任一命中直接「不建議收托／轉介」：

- 需 24 小時醫療處置（抽痰、呼吸器）
- 法定傳染病急性期
- 嚴重攻擊行為且無法團體照顧
- 超出該機構收托條件（依各機構自訂：如完全臥床鼻胃管視機構而定）

未觸紅線者，進決策矩陣：

| 跌倒燈號 ＼ 人力成本 | 低 | 中 | 高 |
|---|---|---|---|
| 🟢 綠 | ✅ 建議開案 | ✅ 建議開案 | ⚠️ 評估量能 |
| 🟡 黃 | ✅ 建議開案 | ⚠️ 評估量能 | 🔶 需個案會議 |
| 🔴 紅 | ⚠️ 評估量能（須防跌配套） | 🔶 需個案會議 | ⛔ 不建議／轉介 |

## 5.【項目二】在案中個案的內容 — 資料分析

### 5.1 案中要管的四塊

對照「照管家」既有欄位 + 你的三大功能，案中資料分析分四塊：

1. **監測**（多模態手環）
2. **異常預警**（生理閾值 + 離床/跌倒）
3. **護理紀錄生成**（語音 → SOAP）
4. **家屬聯絡簿 + 趨勢預警**（每日彙整 + BPSD 預警）

### 5.2 多模態即時監測資料

| 來源 | 訊號 | 頻率 | 備註 |
|---|---|---|---|
| 智慧手環 | 心率、血氧 SpO₂、體表溫、步數、活動量、加速度（跌倒偵測） | 心率每分鐘；事件即時 | MVP 用模擬資料 |
| 人工量測 | 血壓、血糖、體重（照服員定時量） | 定時 | 對照照管家「生命徵象紀錄」 |

### 5.3 異常預警邏輯

**生理閾值表**（成人靜息參考值，實際須依個人 baseline 校準）：

| 指標 | 🟢 正常 | 🟡 觀察 | 🔴 警示 / 緊急 |
|---|---|---|---|
| 心率 (bpm) | 60–100 | 50–59 / 101–119 | <50 或 ≥120 |
| 血氧 SpO₂ (%) | ≥95 | 90–94 | <90（紅）；<85 緊急 |
| 體溫 (°C) | 36–37.4 | 37.5–37.9 | ≥38 |
| 收縮壓 (mmHg) | 90–139 | 140–179 / 85–89 | ≥180 或 <85 |
| 舒張壓 (mmHg) | 60–89 | 90–109 | ≥110 |

**事件預警邏輯**：

```text
# 離床（對應 Demo 畫面二「3號床異常離床」）
if 離床 and 未歸位時間 > 10 分鐘        → 🔴 紅色警報 + 嗶嗶聲 + 定位上螢幕
elif 離床 and 未歸位時間 in [5,10] 分鐘  → 🟡 觀察提示
# 跌倒
if 加速度計偵測到跌倒特徵              → 🔴 立即緊急派人
# 走失（若有區域定位）
if 離開安全區域                        → 🔴 走失預警 + 門禁連動
```

> 分級：🟢正常 / 🟡觀察（照服員注意） / 🔴立即處理。所有判斷在地端完成，不需連外網。

### 5.4 生成式 AI 護理紀錄（語音 → SOAP）— 對標 Jubo

**輸入**：照服員按麥克風，用台語/國語口述。
**地端 NER 抽取**：對象、時間、生理數值、行為、情緒、用藥、事件。
**結構化為 SOAP**（自動帶入手環當下數值）：

範例輸入（你原本的句子）：
> 「陳奶奶今天早上血壓正常，但下午吃藥時有點抗拒，情緒不太好。」

輸出 SOAP：

| 欄位 | 內容 |
|---|---|
| **S**（主觀） | 陳奶奶下午服藥時表達抗拒，情緒不佳 |
| **O**（客觀） | 上午血壓 128/78 mmHg（正常，手環/量測帶入）；服藥時出現抗拒行為 |
| **A**（評估） | 疑似 BPSD 情緒/服藥配合度議題，非生理急性異常 |
| **P**（計畫） | 觀察情緒變化；下次服藥調整引導方式；記錄並交班護理師評估 |

> **對標 Jubo 的兩個要點**：①「基於既有資料生成、減少幻覺」——O 欄的數值一律來自地端實測，不讓 AI 編；②「專業人員主導最終判斷」——AI 出草稿，護理師按一下確認/修改才入檔。**差異化**：Jubo 這段在雲端，ARKAI 在地端，只有「潤稿成合規措辭」才選擇性去識別上雲。

### 5.5 每日家屬聯絡簿草稿

彙整當日 → 自動生成家屬版（去專業術語）：

- 生理趨勢（今日心率/血氧平穩、血壓正常）
- 活動參與（上午復健、下午手作課參與良好）
- 飲食（午餐 8 分、下午點心正常）
- 情緒與特殊事件（下午服藥略抗拒，已安撫）

> 對應「省 70% 行政打字」。地端彙整；只有「白話改寫」可選上雲。對照照管家的「電子化家庭聯絡簿」，ARKAI 的加值是**自動生成草稿**而非空白表單。

### 5.6 趨勢分析 / BPSD 暴動預警（延伸）

累積去識別化的長期生理趨勢，跨天偵測異常：

```text

if 步數連續3天暴增 and 夜間離床次數上升 and 靜息心率上升
   → 🟠 BPSD 暴動預警：提示照服員提早介入，避免衝突/走失
```

> 這是「事後紀錄」升級為「事前預防」的鉤子；MVP 可先做簡單規則版展示概念。

## 6.【延伸】手環體能鑑測（fitness assessment）

> 你的想法：「手環部分可能可以調整鑑測體能」。這條很有價值——它把手環從「被動監測」升級成「主動評估工具」，並接上長照的**自立支援 / 自立訓練**主軸（照管家有「自立訓練記錄」欄位、鑫淼有自立支援設施）。

### 6.1 手環能量出的體能指標（對應臨床 SPPB）

長照體能標準工具是 **SPPB 簡短身體功能量表**（平衡、4 公尺步速、5 次坐站，各 0–4，總 0–12）。手環可輔助/自動化其中幾項：

| 手環可算 | 對應臨床意義 | 用途 |
|---|---|---|
| 靜息心率趨勢（下降＝變好） | 心肺適能 | 訓練成效 KPI |
| 每日步數 / 活動分鐘 | 活動量、衰弱 frailty | 衰弱篩檢 |
| 步速估算（固定路線步數/時間） | SPPB 步速項 | 移動能力、跌倒風險 |
| 運動後心率恢復速度 | 心肺儲備 | 體能分級 |
| 坐站動作偵測（加速度計） | SPPB 坐站項 | 下肢肌力 |

### 6.2 三個用途接回主線

1. **開案 baseline**：入案時做一次體能鑑測 → 設定康復目標（接項目一）。
2. **案中成效追蹤**：康復與認知課程（簡報作息階段 3）後的體能趨勢 → 證明照護有效（接項目二）。
3. **對家屬/政府的 KPI**：「王奶奶 3 個月步速從 0.6→0.8 m/s、靜息心率降 8 bpm」——這是機構向家屬證明價值、向政府核銷成效的**硬數據**，也是去識別化後可上雲比對常模的資產。

> MVP 階段：用模擬手環資料展示「體能鑑測卡」即可（步速/活動量/心率恢復三個數字 + 趨勢箭頭）。

## 8. 資金來源與政策套利（補助紅利）

### 8.1 市場紅利：長照預算爆發性成長

| 年度 | 長照預算 | 備註 |
|---|---|---|
| 2016（長照 1.0） | 54 億 | 起點 |

### 8.2 政策套利三階段（已於 2026-07 查證）

> 查證結論：提案的三個計畫**都真實存在、名稱大致對得上**，但金額與時程需修正。**關鍵限制：多數計畫明訂「同一內容不得重複領取其他政府補助」**，故三階段必須切在不同範疇/交付物上，不能疊在同一件事「1:1 放大」。

| 階段 | 正式計畫名稱 / 主辦（查證） | 金額（查證） | 時程（2026-07 查證） |
|---|---|---|---|
| **一 · 打通路** | **新創驅動高齡驗證獎勵**（中小新創署「次世代產業新創淬鍊計畫」） | **定額 100 萬**，免償還，須自籌（非零） | 115（2026）梯次已於 **2026/4/30 截止**；最快下一梯 116（2027）。執行期至 2026/10/31 |
| **二 · 拿通行證** | **高齡普惠科技研發與實證補助計畫**（產發署 TIIP 產業升級創新平台輔導計畫·主題式） | 補助比例最高 **50%**；上限依當年度申請須知 | 年度制（113 梯次受理 2023/12–2024/2）；2026 梯次須查官網公告 |

**查證修正重點：**

1. 階段一是**定額 100 萬**（非提案的 100–200 萬），且 **2026 梯次已截止**——7 月的現在最快是 2027 梯次。
2. 階段一結案硬性要求：**完成 ≥1 案高齡解決方案 ＋ 場域/產業合作證明 ＋ 登錄社創資料庫**；審查「場域驗證」佔 **40%**——正好吃 MVP 的實測數據。
3. **不可重複補助同一內容**：建議切三個範疇——驗證獎勵做「開案初篩場域驗證」、實證補助做「案中監測＋SOAP 研發」、SBIR/A+ 做「地端閘道平台化」，否則違規追回。
4. **最快入口其實是 SBIR（隨到隨受理）**，不必等年度梯次；提案把它放階段三，實務上可提前申請。

**階段一資格門檻**：2018 後設立之中小企業、實收資本額 ≥200 萬、已完成 POC、一家一案。

**資料來源**：[新創驅動高齡驗證獎勵](https://taccplus-subsidy.com/)、[SBIR 官網](https://sbir.org.tw/)、[A+ 淬鍊計畫](https://service.moea.gov.tw/EE514/tw/aiip/53.html)、[高齡普惠科技研發與實證補助計畫](https://eii.nat.gov.tw/tiip/)（查證日 2026-07-03）。

### 8.4 風險

- 補助有名額 / 時程 / KPI 查核義務，**不能當唯一金流**；現金流仍須靠天使輪＋早期 SaaS 訂閱撐。
- 「免償還獎勵金」仍附成果查核，未達標可能追回。
- **不可重複補助**：多數計畫明訂同一內容不得重複領取其他政府補助——三階段須切不同範疇，否則違規追回。
- **時機**：驗證獎勵 2026 梯次已於 4/30 截止（現為 7 月），最快 2027 梯次；**SBIR 隨到隨受理，是當下唯一可立即申請的入口**。

## 附錄：量表速查

**Barthel Index（巴氏量表，ADL，0–100）** — 10 項：進食、洗澡、修飾、穿脫衣物、大便控制、小便控制、如廁、移位、行走、上下樓梯。
分級：0–20 完全依賴｜21–60 嚴重依賴｜61–90 中度依賴｜91–99 輕度依賴｜100 獨立。

**Lawton IADL（工具性，0–8）** — 使用電話、購物、備餐、家務、洗衣、交通、服藥、理財。

**NPI-Q（BPSD，12 症狀 × 嚴重度 1–3）** — 妄想、幻覺、激動/攻擊、憂鬱、焦慮、欣快、冷漠、去抑制、易怒、異常動作行為、夜間行為、食慾。

**Morse 跌倒量表（0–125）** — 跌倒史、續發診斷、行走輔具、靜脈輸液、步態、心智狀態。本報告採日照改良版（見 §4.3）。

**長照 CMS 照顧管理需要等級（第 2–8 級）** — 依 ADL/IADL/認知/情緒行為/照顧者負荷等 8 面向核定，對應四包給付（照顧及專業服務、交通接送、輔具/居家無障礙、喘息服務）。開案可對照個案的 CMS 等級。

**SPPB 簡短身體功能量表（0–12）** — 平衡、4 公尺步速、5 次坐站，各 0–4。手環可輔助步速/坐站/活動量（見 §6）。
