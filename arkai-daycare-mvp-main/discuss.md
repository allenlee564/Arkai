## 2026-07-04

### 已收斂的結論

1. **定位 / 競品**（報告 §2）：產品 = **地端物理隔離的 Edge AI**，非雲端 SaaS。競品 = Jubo（雲端 AI 紀錄）、照管家（日照 SaaS）、AIoT 監測廠；**鑫淼天使居 = 客戶/場域，非競品**。護城河 = 創新者兩難 + 2026 法規窗 + 去識別化閘道，**不是功能組合**。

2. **資料流骨幹**（報告 §3）：L0→L6 地端 NER 安全分流。含 PII→地端 RAG；去識別→可雲端；不確定→人工確認。

3. **雲端模擬邊界（核心爭議）**：
   - Litmus test：「**本地模型做不出來，還有沒有產品?**」答「改用雲端」= 倒反天罡（雲端從鷹架變退路 → 護城河拆光）。
   - **去識別必須留地端**；只有 **SOAP 生成**可雲端 API 代打，且假資料。
   - → 已抽成 **GitHub issue** 請 PM 確認。

4. **閹割版元件放置**：除「SOAP 生成」雲端代打外，DB / 去識別 / 預警 / 規則 / 閘道**全真跑地端**（詳見 issue）。

5. **硬體 sizing**：SOAP 生成 = 短上下文抽取+填格式（很輕）。Qwen2.5-7B Q4、一台 **NT$2.5–4 萬 Mac mini / GPU mini-PC**，**3–6 秒離線出** → **「地端資源不足」是偽命題**，且落在智慧長照硬體補助射程內。

6. **UAT**：用機構真實資料 + **斷網測試** + **egress 零 PII 稽核** → 雲端模擬**進不了 UAT** → 倒推本地模型替換死線必須早於 UAT。

7. **補助策略**（報告 §8，已查證 2026-07）：三計畫真實。驗證獎勵**定額 100 萬**（非 100–200）、**2026 梯次已截止**（最快 2027）；**SBIR 隨到隨受理 = 最快入口**；**不可重複補助**同一內容 → 三階段須切不同範疇。
