## 0. 文件目的與範圍

把需求（資料分析報告）轉化為「怎麼做（How）」的工程規格，供 PG（實作）階段照著刻。架構總圖已存在於 repo 的 `arkai_multitenant_v2.mermaid`（三平面）與 L0–L6 資料流圖，本文不重畫。

## 1. 架構設計

### 1.1 系統分層與組件（前端/後端/雲端/硬體端 Edge）

本系統有兩層硬體端，這是與一般「device 直連雲」IoT 的關鍵差異：

| 層 | 組件 | 職責 | 部署位置 | 技術（建議） |
|---|---|---|---|---|
| 硬體端 · 感測層 | 智慧手環 | HR/SpO₂/加速度（跌倒） | 長輩身上 | BLE |
| 硬體端 · 感測層 | 智慧床墊 / 雷達 | 離床/呼吸/非接觸心率 | 床邊 | MQTT/TLS 或 RS-485 |
| 硬體端 · 地端主機（★核心） | Ingestion 服務 | 收端點資料、綁個案代號、落原始資料 | 機構內網 appliance | Mini-PC / Mac mini / Jetson |
| 硬體端 · 地端主機 | AI 服務（地端小模型 + NER + ASR） | SOAP 生成、去識別、量表輔助 | appliance | Ollama + Qwen2.5-7B Q4、faster-whisper |
| 硬體端 · 地端主機 | 規則/閾值引擎 | 開案燈號、人力成本、即時預警 | appliance | 純程式邏輯 |
| 硬體端 · 地端主機 | 地端 RAG | 院內 SOP/照護指引檢索 | appliance | pgvector |
| 硬體端 · 地端主機 | 本地資料庫 | 見 §2 | appliance | PostgreSQL(+Timescale+pgvector) / SQLite |
| 硬體端 · 地端主機 | egress 閘道 | 唯一對外出口，只出去識別資料 | appliance | 見 §3.4 |
| 前端 | 機構智慧照護戰情牆 | 即時狀態、警報、開案初篩、SOAP 助理 | 機構內平板/PC | Web（React）+ WebSocket |
| 前端 | 家屬聯絡簿 | 家屬版每日彙整 | 家屬手機 | Web/推播 |
| 雲端 · 去識別資料平面 | 雲端 LLM 輔助 | 文獻/術語摘要/護理措辭潤稿 | GCP/AWS/自建 | 只收去識別資料 |
| 雲端 · 去識別資料平面 | 去識別常模庫 | 跨租戶趨勢常模（網路效應） | 雲 | 不含個案連結 |
| 雲端 · 控制平面 | Fleet 管理 | OTA、監控、設定下發、多租戶權限管理 | 雲 | 只中繼、不碰資料 |

> **雲端選型（待確認）**：兩個雲端平面只承載去識別資料，選型限制低。基於本地信任訴求，建議資料落地台灣 region 或自建。詳見 §6。

### 1.2 通訊協定設計（逐條鏈路）

| # | 鏈路 | 傳輸方式 | 方向 | 資料類 | 安全機制 |
|---|---|---|---|---|---|
| L-a | 手環 → 地端主機 | 藍牙低功耗 | 上行 | 生理串流 | 配對綁定金鑰 |
| L-b | 床墊/雷達 → 地端主機 | 加密網路傳輸 或 序列埠 | 上行 | 事件/串流 | 每設備憑證 |
| L-c | 語音 → 地端主機 | 端點錄音上傳 → 本地語音辨識 | 上行 | 語音（含個資） | 不出機構，本地轉逐字稿 |
| L-d | 前端戰情牆 ↔ 地端主機 | 加密網頁請求 + 即時推播連線 | 雙向 | 臨床資料 | 加密傳輸 + 登入權限驗證 |
| L-e | 地端主機 → 去識別平面 | 加密網頁請求 + 雙向憑證驗證 | 僅上行 | 去識別趨勢/術語查詢 | 雙向憑證 + 簽章 + 出口掃描 |
| L-f | 地端主機 ↔ 控制平面 | 加密網頁請求 + 雙向憑證驗證 + 定期回報 | 雙向（中繼） | 設定/更新/監控資料 | 雙向憑證 + 權限驗證，不碰臨床資料 |

**設計原則**：

- 感測層只跟本地 appliance 說話，不直連雲（縮小攻擊面）。
- appliance 對雲一律主動對外連線（拉取設定、推送去識別資料），雲端無法主動連入 appliance，機構不需 IT 開防火牆孔。
- 即時警報走即時推播機制直送戰情牆，不用前端輪詢等待。

### 1.4 端到端資料流

以下為三條主要資料流程，以步驟方式呈現（詳細技術層級資料流見報告 §3.3–3.5）：

**流程 A：案中語音 → SOAP**

1. 手環串流、床墊事件、照服員語音三路資料同時進入地端主機。
2. 地端主機將原始資料落地保存，並執行醫療實體辨識（NER）。
3. 含個資的內容一律留在地端處理：語音先經本地語音辨識轉逐字稿。
4. 地端小模型組裝 SOAP 護理紀錄草稿，O 欄（客觀數值）一律帶入手環/量測的實際數據，不讓 AI 自行生成數字。
5. 草稿寫入系統並即時推播到戰情牆。
6. 護理師確認後正式入檔；若選擇潤稿，僅將去識別後的評估與計畫欄位送雲端潤飾用語。

**流程 B：即時離床預警**（安全關鍵，全程本地、斷網照跑）

1. 床墊偵測到離床事件，傳入地端主機。
2. 地端閾值引擎判斷離床時間是否超過設定門檻（如10分鐘）。
3. 觸發後立即寫入警報紀錄。
4. 即時推播到戰情牆，畫面閃紅並發出警示音。
5. 全程不經任何雲端服務，機構網路斷線也不受影響。

**流程 C：🆕 入住前面談評估 → 面談輔助報告**（發生在開案評估提交之前）

1. 評估人員填寫或匯入福利資格、家庭支持、生理需求、ICOPE 四大構面資料（人工填表 或 §6.x 所述不填表匯入來源）。
2. 地端主機彙整計算，產出面談輔助報告（狀態：草稿待面談使用）。
3. 前端列印或攜帶報告去做入住面談。
4. 面談後由評估人員人工確認，轉入正式開案評估流程（既有流程③）。
5. 產出正式開案決定結果。

> **設計原則**：本流程先於「③開案評估提交」，面談輔助報告不等於開案決定，僅供評估人員帶去面談時參考；面談後才走既有開案評估流程產生正式決定。

## 2. 資料庫與資料結構設計

**DBMS 選型**：地端主機用 PostgreSQL 16（+ TimescaleDB 生理時序、+ pgvector 向量檢索）；最小封裝可退回 SQLite。

> **核心設計原則 — PII 與臨床資料分離**：個案代號是內部代號（非真實身分），真實個資只存在獨立的個資保險庫（欄位級加密）。所有臨床/監測資料表只引用個案代號，達成「去識別 by construction」——匯出資料時天生不帶身分。

### 2.3 硬體資料暫存與斷線補傳機制

兩層緩衝，對應兩層硬體：

**① 感測端點 ↔ 地端主機（本地鏈路斷）**

- 端點內建暫存區（手環離線暫存數小時、床墊暫存事件）。
- 每筆資料帶設備代號、序號、時間戳；重連後回補。
- 地端主機以「設備代號+序號」組合唯一性冪等去重，重複補傳不會重算。

**② 地端主機 → 雲端（網路斷）**—— 這是設計特性，不是缺陷

- 核心臨床功能（開案、預警、SOAP、紀錄）不依賴雲端，斷網 100% 照跑（離線自治）。
- 對雲的去識別上傳走「暫存待送」機制：資料先寫入本地暫存佇列，附上唯一識別鍵。
- 網路恢復後，背景程式依唯一識別鍵冪等傳送；雲端重複收到也只記一次。
- 控制平面設定/更新為地端主機主動拉取，斷網期間沿用最後一次設定，恢復後續拉。

## 3. 資安與防護設計

> **威脅模型（簡）**：主要威脅＝①個資外洩（傳輸/儲存/雲端集中）②未授權存取 ③設備假冒 ④多租戶資料串接 ⑤金鑰外洩。核心對策＝個資不出機構 + 唯一去識別出口 + 每設備身分 + 硬體金鑰。

### 3.1 傳輸安全

| 鏈路 | 傳輸安全 |
|---|---|
| 手環 → appliance | 藍牙配對綁定金鑰，敏感資料應用層再加密 |
| 床墊/雷達 → appliance | 加密網路傳輸，每設備憑證；序列傳輸走實體隔離內網 |
| 前端 ↔ appliance | 加密網頁連線 + 加密即時推播連線 |
| appliance → 雲端（兩平面） | 加密連線 + 雙向憑證驗證 + 資料簽章 |

> **原則**：全鏈路禁明文；appliance 只開出站，雲端不可主動連入。

### 3.2 認證與授權

- **感測端點 → 地端主機（本地）**：每設備獨立憑證/金鑰，註冊於設備清單；未註冊設備拒收。
- **地端主機（Node）→ 雲端**：雙向憑證（每台主機一張，建置時簽發）+ 短期權杖做 API 授權。主機身分綁定機構代號，雲端驗憑證 + 權杖 + 租戶範圍，杜絕跨租戶存取。
- **使用者 → 前端**：角色權限控管（護理師/社工/照服員/管理員）+ 登入權杖；個資保險庫讀取限護理師/管理員角色，且每次存取寫入稽核紀錄。

### 3.3 設備安全與金鑰管理

- **金鑰絕不寫死於程式**：主機私鑰、資料加密金鑰存於硬體安全模組，主金鑰永不離開硬體；資料金鑰由主金鑰包裝，支援輪替。
- **Wi-Fi 密碼 / API 金鑰 / 憑證**：存於作業系統安全儲存區或環境變數注入，不進版本控制、不進映像檔；建置流程走安全上線程序（首次配對 + 憑證簽發）。
- **安全開機 + 簽章更新**：韌體/模型更新需簽章驗證，防止竄改推送。
- **最小權限**：各服務以獨立低權限帳號執行；資料庫帳號分讀寫角色。

### 3.4 去識別出口契約（ARKAI 專屬）

這是產品護城河的技術實作，比一般 IoT 資安多一層：

1. **唯一對外出口** = 出口閘道；程式上只允許去識別趨勢庫 + 匿名術語查詢兩類資料出門。
2. 出門前跑**個資掃描**（規則比對 + 醫療實體辨識二次校驗）；命中個資 → 攔下、不送、記錄失敗結果。
3. 每次對外傳送皆記錄（傳送資料類型、掃描結果、目的地）→ 可稽核「零個資封包」。
4. 這條契約同時是驗收項目（斷網測試 + 出口抓包驗證）。

> 🆕 **提醒**：家庭支持評估表中的家系圖/生態圖資料含家屬關係資訊，屬個資等級敏感資料，出口掃描規則需明確涵蓋此表，避免因欄位為結構化資料格式而被規則遺漏。

### 6.x 🆕 不填表匯入架構 —— 可行性分析

**問題定義**：入住前五大構面（福利資格、家庭支持、生理需求、生活背景、ICOPE）目前預設為評估人員手填表單；本節評估是否能改為系統自動匯入，減少手填負擔。

**可能匯入來源盤點**

| 來源 | 可匯入內容 | 技術可行性 | 備註 |
|---|---|---|---|
| 既有機構管理系統（如照管家）匯出資料 | 個案基本資料、既有生命徵象紀錄、過去照顧計畫 | 高（結構化欄位對應） | 需取得機構授權匯出格式 |
| 政府福利資格資料庫 | 福利身分、身障手冊狀態 | 中（需公部門介接窗口與法規授權） | 短期內建議仍以人工上傳證明文件為主 |
| 家屬線上填寫小問卷 | 家庭支持、生活背景、照顧人力 | 高（表單線上化，非AI匯入問題） | 屬於「減少手填」但非「不填表」 |
| 語音面談口述 → 本地語音辨識結構化 | 生理需求描述、生活背景、家庭支持敘述 | 中（沿用既有本地語音辨識+實體辨識技術路徑） | 需驗證口語敘述轉結構化欄位（如量表分數）的準確度，不能全靠AI自動判斷分數 |

**風險與限制**

1. 福利資格類（身障手冊、福利身分）具法律效力，**不建議由 AI 自動判讀認定**，仍需人工核對證明文件，AI 僅能輔助預先帶入欄位供人工確認。
2. 家系圖/生態圖屬於社工專業繪製工具，語意複雜，短期內較難單靠語音/文字自動生成，建議仍搭配前端繪圖介面人工確認。
3. 憂鬱情緒等量表分數屬於臨床判斷結果，若由語音敘述反推分數，需經人員複核，比照現有SOAP生成中數值標註來源的防幻覺設計。

**建議：分階段導入**

| 階段 | 範圍 | 說明 |
|---|---|---|
| 階段一（MVP可做） | 既有機構系統資料匯入 + 家屬線上問卷 | 技術風險低，立即可減少部分手填 |
| 階段二 | 語音口述 → 生活背景/家庭支持描述自動帶入草稿 | 沿用既有技術路徑，人工確認後入庫 |
| 階段三（待確認） | 政府福利資格資料庫介接 | 需法規與跨機關窗口，非技術問題為主 |

## 附錄：Enum 定義與名詞

**分類定義**

- 生理指標：心率、血氧、體溫、收縮壓、舒張壓、步數、活動量
- 監測事件類型：離床、跌倒偵測、離開安全區域
- 警報等級：綠燈、黃燈、紅燈、緊急
- 巴氏量表等級：0–20完全依賴｜21–60嚴重依賴｜61–90中度依賴｜91–99輕度依賴｜100獨立
- NPI-Q症狀：妄想、幻覺、激動攻擊、憂鬱、焦慮、欣快、冷漠、去抑制、易怒、異常動作、夜間行為、食慾
- 使用者角色：護理師、社工、照服員、管理員
- 路由決策：本地、雲端、人工
- 🆕 福利資格類別：65歲以上失能老人、55歲以上失能原住民、50歲以上失智症者、身障身分、福利身分
- 🆕 照顧者類型：家人、外籍看護、付費本地照服員、無
- 🆕 家庭支持程度：低、中、高
- 🆕 行動能力分類：獨立行走、助行器輔助、輪椅、臥床
- 🆕 視力狀態：正常、矯正後尚可、未矯正受損、失明
- 🆕 聽力狀態：正常、受損、失聰
- 🆕 個案狀態（ICOPE）：入住前、在案中、結案、轉介
- 🆕 面談報告狀態：草稿待面談、已用於面談、已被取代

**名詞**

- **appliance**＝機構地端主機
- **egress 閘道**＝唯一對外出口
- **去識別**＝移除或轉換可識別個人身分的資訊
- **PII**＝個人可識別資訊
- **mTLS**＝雙向憑證加密連線
- **RAG**＝檢索增強生成
- **SPPB**＝簡短身體功能量表
- 🆕 **ICOPE**＝Integrated Care for Older People，整合性長者照護指引（WHO）
- 🆕 **家系圖（genogram）**＝呈現家庭成員結構與關係之工具
- 🆕 **生態圖（ecomap）**＝呈現個案與周邊資源/支持系統關係之工具
- 🆕 **面談輔助報告**＝入住面談前產出、供評估人員參考但非最終開案決定之報告
