## 協作規則（2026-07-07 起）

**`main` 不直接改 / 不直接 push**：除 repo owner（gray，技術擔當/維護者）外，所有變更走 **branch → Pull Request → gray review/merge**。完整流程、force-push 禁令與 **AI 使用鐵則**見 **[AGENTS.md](./AGENTS.md)**（人與 AI 共用正本；Cursor/Copilot/Codex 自動讀取，網頁版 AI 開工先貼全文）。

- 理由：main 是文件正本（spec/PRD 互相仲裁的基準），直推會繞過同步規則造成多版並存、格式毀損等漂移（2026-07-07 已發生一次）。
- GitHub free 私有 repo 無法硬性設 branch protection（需 Pro 或轉 public），故此規則靠團隊約定 + git 可 rollback 執行。

## 一句話定位

不是把競品功能組起來，而是賭一個**架構級錯位**：在 Jubo／照管家因雲端商業模式無法輕易跟進的「地端」這一側，先拿下對雲端最有顧慮的日照機構，再做成機構內 IoT 必須對接的**地端去識別化閘道**。護城河 = 創新者兩難 + 2026 法規時間窗 + 閘道標準（「地端」本身正在商品化，單靠它很薄）。

> 競品 = Jubo（雲端 AI 紀錄）、照管家（日照 SaaS）、AIoT 監測廠商。鑫淼天使居是**客戶/場域**，不是競品。
